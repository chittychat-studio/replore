# Changelog

All notable changes to Replore (web page, Claude Code plugin, MCP server and script) are listed here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow
[Semantic Versioning](https://semver.org/). Each line names the SPEC rule it ships; `SPEC.md` has the full rule.
How to cut a release: README, Development (SPEC RS81).

## [Unreleased]

### Distribution and Pro
- Directory-ready manifest: homepage, documentation, support and privacy links, author URL and a 512x512 icon
  generated by `ops/make_icon.py`; the marketplace entry has the same description plus a category and tags; the skill
  is named `find` and pre-approves only its own scripts (RS85).
- The optional security-log hook runs in exec form (`python3` + the script path, no shell), so it no longer fails
  under PowerShell and meets the directory checklist; unset `REPLORE_SECURITY_LOG` still means an immediate, silent
  exit (RS25).
- Listing pack: `docs/LISTING.md` (Anthropic directory, MCP registry, PulseMCP, Glama: owner steps and copy),
  `pyproject.toml` for the stdlib-only PyPI package `replore-mcp` (commands `replore-mcp` and `replore`) and
  `server.json` for the registry entry `io.github.chittychat-studio/replore` (RS86).
- Pro keys are now Stripe-backed (signed subscription tokens); Polar removed. A key is `rp.<Stripe subscription
  id>.<HMAC signature>`: the server checks the signature first (a forged key never reaches Stripe), then the
  subscription with a restricted, read-only Stripe key (3 s deadline, no redirects, 10-minute verdict cache by SHA-256,
  codes-only logs); active or trialing with a Replore Pro price gets the plugin key's rights: the meaning route and no
  per-IP limit. Off until `STRIPE_SECRET_KEY`, `PRO_SIGNING_SECRET` and `PRO_PRICE_IDS` are set (403 `pro_off`) (RS87).
- `POST /api/pro/claim` turns a paid Stripe Checkout Session into a Pro key (403 `not_paid` or `not_pro`, 404
  `unknown_session`, 503 `stripe_error`; 5 a minute per address; nothing stored) (RS90).
- Plugin, script and MCP server read the Pro key from `REPLORE_KEY` (the older `REPLORE_PLUGIN_KEY` still works) and
  send it only to Replore's hosts, never through a redirect; `find_repos` gains an opt-in `semantic` flag with a
  `description`. README has a Replore Pro section (how to buy, where the key appears, how to set it) and PRIVACY a
  row for the key (RS87).
- Web: when this browser's storage holds a Pro key (`replore.key`), the page sends it with its relevance checks in the
  same header. PRIVACY has the row (RS87, RS43).
- `docs/MONETIZATION.md`: the owner's monetisation plan with a status per step and the owner's account checklist (RS88).
- "Leo, Pro" window and a Pro button in the top menu: the sign-up offer line, monthly and yearly Stripe Payment Links
  (a prefilled promotion code allowed), "I have a key", save or remove a key kept in this browser, and the saved key
  shown back with Copy buttons for it and for the plugin's `REPLORE_KEY=` line. Hidden until the owner sets `PRO_URL`
  in `web/pro-core.js`; the privacy window names the key and Stripe (RS89).
- New page `/pro`: the same window as a page, and where a buyer lands after Stripe checkout to get their key (shown,
  copyable, saved in the browser that bought it; never saved over another key by a link). Says "Keys are not on sale
  yet." until `PRO_URL` is set. In the footer and the sitemap (RS90, RS80).

### Fixed
- The evals page is linked, canonicalised and listed in the sitemap as `/evals`; Cloudflare Pages redirects `evals.html` (RS80, RS84).

### Added
- SEO basics: `robots.txt`, `sitemap.xml`, a canonical link and a 404 page in the site's look; the pages.dev to
  custom-domain 301 is documented as a Cloudflare Bulk Redirect (RS80).
- The CLI and MCP server retry an empty search with up to two broader searches, like the web page, and say so in a
  `note` (also in `--json`, where an empty result now says why) (RS78a).
- `mcpServers` in `plugin.json`: `/plugin install` registers the `find_repos` and `check_repos` MCP tools in Claude Code (RS32a).
- This changelog and a release workflow that checks the tag against every version and publishes the matching
  section as the GitHub release notes (RS81).
- Opt-in trust sort: "Trust (top 5)" on the web, `--rank trust` in the script, `rank: "trust"` in the MCP tool
  re-order only the top 5 by Scorecard, Maintained and known vulnerabilities; the default ranking is unchanged and
  RX3 is amended to allow this one opt-in (RS82).
- Licence check for a closed-source product: "I'll sell it (closed source)" on the web, `--selling` in the script,
  `selling: true` in the MCP tool flag GPL/AGPL-style repos and name the conflicting picks in the plan prompt; nothing
  is removed or re-ordered (RS83).
- "How ranking is tested": `evals.html` publishes every fit and hybrid eval case from `evals/`, generated by
  `ops/build_evals_page.py` and kept in sync by a test (RS84).

### Fixed
- README, SPEC, PRIVACY, the skill and AGENTS.md described the old five-button card, an old default AI model,
  `--top 10` and only one MCP tool; they now match the code, and a test guards it (RS63, RS34e, RS51).
- Em dashes in visitor copy: the build-plan prompt, the trust panel, the "How we searched" notes and the similar-repo hint
  (and the same trust wording in the script). The RS66 test had a regex slip that skipped most strings; fixed (RS66).
- README described a GitHub Pages `pages` workflow that no longer exists (RS22, RS40).

### Security
- The web's build-plan and launch prompts now say repo names and descriptions are data, never instructions, like
  the MCP server's preamble (RS9, RS25).

## [0.4.0] - 2026-10-22

Everything below shipped under version 0.4.0, from the 0.3.0 release through 2026-10-23.

### Added
- "Safe to build on?" trust check: OpenSSF Scorecard, known vulnerabilities via deps.dev and OSV.dev, an install
  command, beginner-friendliness and the latest release, on web cards (RS53) and in the plugin, script and MCP
  server (`scout.py --trust`, `scripts/trust.py`, `check_repos`), kept in sync by shared test cases (RS56).
- Explore links on result cards: GitDiagram, Gitingest, DeepWiki, GitHub1s and github.dev (RS51).
- Tagline "The repo scout for vibe coders. Find it before you build it." (RS54); link-preview image and README
  banner (RS57).
- Home page: a live product demo over an ASCII globe (RS61, RS62), then the studio stage with Leo, the scout bot
  (RS65, RS67, RS68); explainer video and the Tour window that plays it (RS64, RS72, RS73, RS75).
- Results as compact cards with a filter panel (licence, type, language, stars, updated), a sort menu and a Details
  side panel (RS63, RS67, RS71); tabbed bento Trending (RS63).
- The build-plan prompt asks for a design mockup before the PRD (RS28h) and makes Governor setup step 0 (RS28i).
- Launch it with Leo: a hosting plan and a before/after go-live checklist, handed to your own AI (RS79).
- An empty web search retries broader before giving up; errors are shown where you are looking (RS77, RS78).
- Smooth and scroll-driven motion, reduced-motion safe (RS69, RS76).

### Changed
- Fit ranking asks GitHub for 50 results per search; tail matches rank after the head (RS4b, RS5c).
- One filter row of combinable switches (RS29d), later the filter panel (RS67).
- Script and media URLs carry a content hash, so a deploy is never hidden by a cached file (RS52, RS76).
- One type family site-wide; copy and polish passes (RS65, RS70, RS74).

### Fixed
- The harm filter no longer drops ordinary repos that mention "crack", "DDoS" or "keygen" (RS18a).
- The eval and plugin keys are only ever sent to Replore's own hosts (RS34h); keys split by purpose (RS34g).
- Query length counted in UTF-16 units and trimmed like JavaScript, so web and plugin build the same query (RS4b, RS29b).
- The security-log hook can never block a prompt (RS25); results area is not a live region (RS46).
- CI reports the `ci` check the main ruleset requires (RS50); duplicate SPEC rule IDs fail CI.

### Removed
- Emoji and glyph icons, in the page and in repo descriptions on cards (RS55, RS58).
- The 60% verdict cap in the relevance check (RS34f).
